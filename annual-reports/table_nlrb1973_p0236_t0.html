HEADING ANOMALY (most important caveat): under the "RM cases" spanner the two sub-headings appear printed in the order "Percent" then "Number", reversed relative to the other four panels, which all read "Number" then "Percent". The data beneath them are plainly Number then Percent (Total, all = 971 then 100.0; 477 then 49.2; etc.), matching the other panels, so this looks like a typesetting error in the original. I have transcribed the headings as printed rather than silently reordering them. Because the scan is 1-bit and the words are small, there is some chance this is a misreading of the scan rather than a genuine misprint; a user who needs the headings verbatim should re-check that cell. Column placement of the RM *values* is not in doubt. DECIMAL POINTS RESTORED: this scan drops many faint periods. Numerous percent cells render as e.g. "100 0", "11 0", "49 2", "35 8" with a gap where the decimal point should be, while neighbouring cells in the same column show the point clearly ("100.0", "67.5", "41.1"). Every percent in this table is a one-decimal figure, which I confirmed by recomputing against the column totals (e.g. UD: 62/202 = 30.7, 109/202 = 54.0; All R: 9,493/14,059 = 67.5). I have therefore written the decimal point in every percent cell. No digits were altered, added or recomputed.
