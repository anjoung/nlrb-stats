p. 293. 22 columns: stub, Total number of situations, then Total (Percent / Cumulative percent), then nine two-column type-of-situation blocks (CA, CB, CC, CD, CE, CG, CP, CA-CB combinations, Other C combinations). Decimal points: in this scan the decimal point in most one-decimal values is very faint and often images as a blank (the Total row prints as "100 0" in seven of the nine type columns and as "100.0" in the other two; body cells show the same mixture, e.g. "28 3", "51 3", "43 0"). Every one of these columns is a one-decimal percent series, so I have transcribed them all with an explicit decimal point. No digits were changed. Column-assignment check: each of the nine type columns and the Total-number column sums exactly to its printed Total-row figure (CA 23,728; CB 6,891; CC 1,448; CD 316; CE 120; CG 39; CP 408; CA-CB 1,832; Other C 345; total 35,127), and the nine type totals sum to 35,127. This makes the column placement of every count reliable. Doubtful cells (transcribed exactly as I read them, not corrected): - "Under 10", CA / Percent by size class: read 26.5; 6,257/23,728 recomputes to 26.4, so the final digit may be a 4. - "Under 10", CC / Percent by size class: read 41.1; 597/1,448 recomputes to 41.2. - "Under 10", CE / Percent by size class: read 51.8; 62/120 recomputes to 51.7. - "900-999", Cumulative percent of all situations: read 89.2; the running sum of the Percent column gives 89.3, and the next row's printed 93.0 is consistent with 89.3 + 3.7. Every other cumulative value in the column matches the running sum exactly. - "Under 10", Percent of all situations: printed 28.3 although 9,898/35,127 = 28.18; the printed cumulative column confirms 28.3 was the figure actually used, so this is the report's own rounding, not a misreading. Empty percent cells: in the type columns a count of 0 is usually followed by a dash rule ("------") in the matching percent cell; a few (e.g. "40-49" CG, "90-99" CG) appear simply blank.
