Decimal points: in this 1-bit scan the decimal point in the percent columns has dropped out of most cells, which print as e.g. "100 0", "87 3", "13 9" with a gap where the point belongs; a few cells retain a visible point ("0.0", "4.6", "86. 1", "4. 2"). I have restored the point in every percent cell, as the restored values are internally consistent (each panel's percent column sums to 100.0) and match Number/Total ratios. "After 10 (k)^2 notice of hearing, total", All C cases / Percent: the cell prints a bare "3" with no visible leading zero, so I transcribed ".3" (18/5,503 = 0.3, and 87.3 + .3 + 12.4 = 100.0). If the source style always carries a leading zero this would be "0.3". "After hearing", N. L. R. A. C cases / Percent: prints a single "0", not "0 0"; transcribed as "0" rather than "0.0". Note the "Before hearing" row leaves the same cell blank (dash rule), so the table is inconsistent here. "Before formal action, total", All C cases / Percent: printed 87.3, whereas 4,800/5,503 = 87.2. This appears to be a deliberate adjustment so the All C percent column sums to exactly 100.0; transcribed as printed. All other arithmetic checks out: panel columns sum to the All C column, component rows sum to their totals, and the three stage totals (4,800 + 18 + 685) sum to 5,503. Blank percent cells in the body are printed as dash rules (-------) and are transcribed as "". In the 10 (k) block the N. L. R. A. and CA panels are entirely dash rules, so those cells are "". Footnote markers appear as raised digits printed to the LEFT of their values in the body ("³ 27", "⁴ 10", "⁴ 9", "⁵ 10", "⁵ 2", "⁶ 160"); per instruction they are written after the value behind a caret. Scan defects: a dark horizontal smudge/fold runs across the "Dismissed" row of the After-hearing block, and small ink specks sit in the All C percent column beside "Withdrawn"/"Dismissed" in the Before-formal-action block.
